## Fix ControlNet duplicate-model dedup asymmetry

**Status: RESOLVED 2026-08-04.**

In D:\dev\SDTD_040_Beta, the StreamDiffusionTD component dedups duplicate ControlNet model_ids only in the live-update path, not at startup — and the backend can't recover from startup duplicates:

Live path: Cnblock() in Scripts\StreamDiffusionTD__Text__StreamDiffusionExt__td.py (lines ~5050-5152) keeps only the highest-weighted entry per model_id before sending /controlnets.
Startup YAML export (same file, lines ~3738-3809) loops the Cn sequence and emits EVERY enabled block with no dedup — two blocks with the same Id produce two YAML entries.
Backend load:_prepare_controlnet_configs in StreamDiffusion\src\streamdiffusion\config.py (lines 251-267) does no dedup, and add_controlnet in StreamDiffusion\src\streamdiffusion\modules\controlnet_module.py (lines 145-200) plain-appends — so the same CN model loads twice and applies additively.
Worse, _update_controlnet_config in StreamDiffusion\src\streamdiffusion\stream_parameter_updater.py (lines 1486-1513) builds current_models as {index: model_id} and only removes CNs whose model_id is absent from the desired config — duplicate entries of a desired model are never removed, so a later live update cannot clean up startup duplicates; existing_index = next(...) only ever updates the first duplicate.
Suggested fixes (pick per judgment): dedup by model_id (keep highest conditioning_scale) in the YAML export loop at Ext ~3743, and/or make_update_controlnet_config collapse duplicate current entries. Note the course doc Session_04 (STREAMDIFFUSION_COURSE\course_v3\Session_04_ControlNet_II_Bodies_and_Drawing.md, step 17) teaches that "only the higher-weighted block survives" after a restart — the fix should make that true. Backend changes must follow the StreamDiffusion repo's git wrapper workflow (scripts/git/*.sh, never raw git commit).

**Resolution:** Both backend fixes taken (a config-source-agnostic fix plus a self-heal fix), backed by a single shared dedup rule instead of two hand-rolled copies:
- New `dedupe_controlnet_configs(configs)` helper in `StreamDiffusion\src\streamdiffusion\config.py`, called at the end of `_prepare_controlnet_configs` — collapses duplicate `model_id`s to the highest `conditioning_scale`, first-occurrence order, logging every drop at INFO. This closes the startup gap for *every* config source (TD Local, the demo app, anything else that loads YAML/JSON through this path).
- `_update_controlnet_config` in `StreamDiffusion\src\streamdiffusion\stream_parameter_updater.py` now (1) dedups the incoming `desired_config` through the same helper before building `desired_models` — this also closes a second creation vector found during plan verification: a stale, unrefreshed `current_models` snapshot could otherwise cause a duplicated `desired_config` to add the *same not-yet-loaded* model twice; (2) removes any pre-existing duplicate indices from the already-loaded pipeline before the reorder/diff pass, so an already-running stream self-heals on its next live update; (3) recomputes `current_models`/`current_config` after those removals, fixing a latent stale-index/`IndexError` risk.
- Frontend belt-and-braces: the YAML export loop in `Scripts\StreamDiffusionTD__Text__StreamDiffusionExt__td.py` (~3734-3822) now dedups the same way as `Cnblock()` — keyed on the post-cross-architecture-correction `cn_id`, keeping the strictly-higher `Weight`, logging drops — so the exported YAML is an honest record of what will actually run even before the backend gets a chance to dedup.
- Regression coverage: new `StreamDiffusion\tests\unit\test_controlnet_duplicate_dedup.py`, 8 tests, covering `_prepare_controlnet_configs` dedup + winner's-preprocessor-survives + pass-through-when-clean, `_update_controlnet_config`'s pre-existing-duplicate removal + duplicate-desired-entries-add-once (the creation-vector case, asserted on call count) + non-duplicated-setup-left-intact, a tie-breaks-to-first-occurrence case, and a full startup→live end-to-end collapse. Verified red (`ImportError` under `git stash`) → green (8 passed) against the fix; neighbor suite (`test_cn_cache_decay.py`, `test_controlnet_residual_merge.py`, `test_config_extraction_golden.py`, `test_param_updater_binding.py` — 31 tests) unaffected.

- Also covers the second ControlNet frontend found during plan verification, `demo/realtime-img2img/`: its startup path goes through `_prepare_controlnet_configs` (Fix B) and its runtime `/controlnet/add` route goes through `update_stream_params` → `_update_controlnet_config` (Fix C), so both fixes protect it without any demo-side change.
